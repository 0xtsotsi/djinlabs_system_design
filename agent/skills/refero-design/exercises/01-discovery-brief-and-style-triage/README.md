# 01 — Discovery brief and style triage

First Refero exercise. Walks through the first 15 minutes of a real Refero
job: form a Discovery brief from limited context, write three style-search
queries (broad / domain / known-brand), name one style you would pull first
from each, and draft a short reference lock before any UI work.

Maps to the **Discovery**, **Tool Routing -> Use Styles First**, and
**Research Workflow -> 1. Research Visual Direction With Styles** sections
of the parent `SKILL.md`. No code, no live MCP needed -- the only artifact
is the inline fill of `problem/TODO.md`.

## When to do this exercise

- You just opened a new design task and want to ship a useful brief before
  the first research call.
- You want to practice the three style-search angles so the habit is fast.
- You want to see what a first reference lock looks like in Refero's format
  before deciding tokens or components.

## What you produce

One markdown file (`problem/TODO.md`) with four filled sections, each kept
to roughly 5-8 lines of plain prose:

1. **Discovery brief** -- the 8-bullet template from the SKILL.
2. **Three style queries** -- one broad, one domain, one known-brand.
3. **Likely hits** -- one sentence per query on which style to pull first.
4. **Reference lock draft** -- primary, preserve, borrow only, token roles,
   reject defaults.

## How to run it

1. Pick ONE small, well-defined product surface (one-line scope, one
   audience). Do not pick a vague surface like "redesign my app".
2. Open `problem/TODO.md` and write the product scope at the top.
3. Fill each section inline with bullet points. Do not exceed one line per
   bullet. Do not invent more scope than the template asks for.
4. Read your draft against the **Synthesis rule** and **Reference Lock**
   sections of the parent SKILL.md. If your lock looks like a centroid of
   three unrelated references, redo it.

## Done when

- All four sections are filled in plain prose.
- No bullet exceeds one line.
- You can answer "what would I build first?" from this draft alone.
- You can name one trait from your "preserve" list that would collapse if
  removed.
